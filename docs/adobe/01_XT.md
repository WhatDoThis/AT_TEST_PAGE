# Adobe Target XT(Experience Targeting) 가이드

> **XT = Experience Targeting(경험 타게팅).** "정해둔 **오디언스(대상)** 에게 **그에 맞는 콘텐츠**를 규칙대로 전달"하는 활동 유형.
> **목적:** XT 개념·동작·세팅을 한눈에. 실제 코드 연동은 `docs/main/04_AT_TEST_PAGE_ADOBE_TARGET_INTEGRATION.md`.

**한 줄 핵심**

```text
오디언스(누구) + 경험(무엇을 보여줄지) → 우선순위(위→아래) 평가 → 맞는 첫 경험 전달
                                                    (아무 데도 안 맞으면 → Default Content)
```

---

## 0. 전체 흐름 (Zero → Live)

XT 활동은 **3단계 가이드 워크플로우**로 만든다(모든 Target 활동 공통: 만들기 → 타게팅 → 목표·설정).

```text
   ┌──────────────────────────────┐
   │ ① Experiences(경험 만들기)   │  위치(mbox) + 경험별 콘텐츠 정의
   └──────────────┬───────────────┘
   ┌──────────────▼───────────────┐
   │ ② Targeting(오디언스 배정)   │  경험마다 오디언스 연결 + 우선순위(순서) 지정
   └──────────────┬───────────────┘
   ┌──────────────▼───────────────┐
   │ ③ Goals & Settings           │  리포팅 소스·목표 지표·우선순위·기간
   └──────────────┬───────────────┘
                  ▼
            Activate(게시) → 방문자 요청 시 평가·전달
```

| 단계 | 할 일 | Target UI |
|------|-------|-----------|
| 1 | 위치(mbox)·경험별 콘텐츠 | Create Activity > Experience Targeting |
| 2 | 경험 ↔ 오디언스 연결, 순서(우선순위) | (같은 마법사 내) Add Experience Targeting |
| 3 | 목표·리포팅·우선순위·일정 | Goals & Settings |

## 1. 핵심 개념 (용어 6개)

| 용어 | 한 줄 | 비고 |
|------|-------|------|
| **Audience(오디언스)** | "누구에게" — 규칙으로 정의된 방문자 집합 | geo·기기·프로필·`crs.*` 등 |
| **Experience(경험)** | "무엇을 보여줄지" — 콘텐츠 변형 1개 | 오디언스 1개 이상과 연결 |
| **Location / mbox** | 콘텐츠가 들어갈 "위치 이름" | 앱/페이지가 호출 |
| **Priority(우선순위)** | 경험 평가 순서(위→아래) | **순서가 결과를 결정** |
| **Default Content** | 어느 오디언스에도 안 맞을 때 보여줄 기본 | 폴백 |
| **Goal Metric(목표 지표)** | 성과 측정 기준(전환 등) | 리포팅용 |

> XT는 **"발견"이 아니라 "전달"** 이다. (어떤 콘텐츠가 좋은지 찾는 건 A/B, 정해진 답을 대상별로 꽂는 게 XT — §2.)

---

## 2. XT vs A/B (언제 무엇을)

| 구분 | **XT(Experience Targeting)** | **A/B Test** |
|------|------------------------------|--------------|
| 목적 | 대상별 **맞춤 전달** | 어떤 변형이 **이기는지 발견** |
| 트래픽 배정 | **오디언스 규칙**으로 결정 | **랜덤** 분할 |
| 통계 | 승자 판정 아님(전달 위주) | 신뢰도·lift 등 통계 검정 |
| 쓸 때 | 답을 이미 앎(geo·등급·신규/재방문 등) | 답을 모름(디자인·문구 실험) |

> 실무 패턴: **A/B로 승자 찾기 → XT로 그 승자를 세그먼트별로 전달.** (예: A/B로 최고 배너 찾고 → XT로 모바일=A, 데스크톱=B.)

## 3. 만드는 순서 (Create)

> 웹은 **VEC(Visual Experience Composer)**, **DOM이 없는 네이티브/서버사이드는 Form-Based**(폼) 컴포저를 쓴다(§6).

1. `Activities > Create Activity > Experience Targeting`.
2. **Visual(VEC)** 또는 **Form** 선택. (Premium은 **Workspace** 선택 가능)
3. **Activity URL**(VEC) 또는 **Location=mbox**(Form) 지정 → Create.
4. **활동 이름** 지정(Untitled Activity 옆 편집).
5. **경험 만들기** — 기본 Experience A(=All Visitors)부터, **Add Experience Targeting**으로 추가(§4).
6. **Goals & Settings** 지정(§5).
7. 우측 상단 **Activate**(게시).

## 4. 오디언스·경험·우선순위 (가장 중요)

### 4.1 경험에 오디언스 배정

- 경험 추가 시 **Add Audience** → 오디언스 1개 이상 선택 → **Assign Audience** → 그 경험의 콘텐츠 편집.
- 한 활동에 **여러 (오디언스 ↔ 경험) 쌍**을 둘 수 있다.

### 4.2 우선순위 = 순서(위 → 아래)

```text
  방문자 도착
     │
     ▼
  경험1 오디언스에 맞나? ── 예 ─► 경험1 전달(끝)
     │ 아니오
     ▼
  경험2 오디언스에 맞나? ── 예 ─► 경험2 전달(끝)
     │ 아니오
     ▼
   …(아래로 계속)…
     │ 전부 불일치
     ▼
  Default Content
```

- **순서가 곧 우선순위.** 위에 있을수록 먼저 평가 → 여러 오디언스에 해당하면 **더 위(높은 우선순위) 경험**을 받음.
- 마법사에서 **드래그&드롭으로 순서 변경**.
- **구체적인 오디언스를 위로**, **All Visitors는 맨 아래**(폴백)로.
  - ⚠️ All Visitors가 위에 있으면 그 아래 경험은 사실상 평가 안 됨(이미 다 잡혀버림).

### 4.3 경험 전환(Switching)

- 프로필이 바뀌면 방문자가 경험 사이를 **전환**한다.
  - 더 높은 우선순위 오디언스에 새로 들면 → 그 경험으로 **상향 전환**.
  - 현재 오디언스에서 빠지고 더 낮은 우선순위에 들면 → 그 경험으로 이동.
  - 어디에도 안 맞으면 → **Default Content**.
- 예외: **단일 경험 XT**는 한 번 들어가면 자격을 잃어도 그대로 유지.

## 5. Goals & Settings (목표·설정)

| 항목 | 내용 |
|------|------|
| **Reporting Source** | **Target** 또는 **Analytics(A4T)**. (Analytics면 목표 지표는 Conversion만, 리포트 오디언스는 report suite 설정 따름) |
| **Goal Metric(목표 지표)** | 성공으로 칠 행동(예: Conversion). 세부 파라미터 설정 |
| **Priority(우선순위)** | 레거시 **Low/Medium/High** 또는 정밀 **0~999**(999 최고). **같은 위치+같은 오디언스에 활동이 겹칠 때** 누가 보일지 결정(§7) |
| **Audiences for Reporting** | 리포트를 특정 오디언스로 필터(기본은 전체 자격자) |
| **일정/노트** | 시작·종료 시각, 메모 |

> 목표 달성 후에도 방문자는 더 높은 우선순위 활동에 들지 않는 한 그 콘텐츠를 계속 봄. 재달성 시 전환(conversion) 추가 카운트.

## 6. 네이티브(앱/서버사이드) XT — VEC 없이

> 핵심: **네이티브 RN에는 DOM이 없어 VEC(시각 편집)를 못 쓴다.** → **Form-Based**로 만들고, **mbox로 콘텐츠(문자열/JSON)를 받아 앱 코드가 해석**한다.

```text
[Target XT 활동(Form)]  Location = mbox, 경험별 콘텐츠(JSON/문자열) + 오디언스
        │
        ▼
[앱]  retrieveLocationContent(mbox)  →  오디언스 평가 → 맞는 경험의 콘텐츠 수신
        │
        ▼
앱 코드가 그 값을 해석해 화면 반영(없으면 Default Content / 앱 기본 UI)
```

- **오디언스 재료:** 앱이 보내는 mbox 파라미터, 프로필, 그리고 **Customer Attributes(`crs.*`)** 등.
  - 예: `crs.recipient_id`·`crs.campaign_label`·`crs.workflow_label`로 오디언스 구성(Customer Attributes 주입은 `03_RECOMMANDATION.md §2.4`).
- **VEC식 "셀렉터로 요소 바꾸기"는 네이티브 불가** — Target은 값만 주고, **어떤 요소에 적용할지는 앱 코드가 결정**.

---

## 7. 활동 간 우선순위(겹칠 때)

- **같은 위치(mbox) + 같은 오디언스**에 활동이 둘 이상이면 → **우선순위(0~999/Low·Med·High) 높은 것**이 표시.
- 동점 시 tiebreaker: ① **오디언스 타게팅이 있는** 활동 우선 → ② 그래도 같으면 **먼저 승인(approve)된** 활동.
- 참고: 방문자가 이미 **A/B·MVT**에 들어가 있으면 전환까지 그 활동 유지. **XT는 매 요청 시 다시 오디언스 매칭**.

## 8. 본 프로젝트 적용 (네이티브 XT 화면)

| 구성 | 값 |
|------|----|
| 화면(라우트) | `app/xttest.tsx` → `XtTestScreen`(푸터 "XT 테스트") |
| mbox | `target-msdk-mbox`(= `config.mobile_env.adobe_sdk_mboxes.offer_sdk_mbox_name`, `common.OFFER_MBOX`) |
| 조회 | "XT 테스트" 버튼 → `retrieveTargetContent(OFFER_MBOX, "default-content")` |
| 기본값 | 오퍼/활동 미설정이면 `default-content` 그대로 반환(미세팅 식별용) |
| 특수 콘텐츠 | 반환이 `event-popup` JSON이면 웹과 동일한 `EventPopup` 모달 표시 |
| 방문자 | `VisitorPanel` — tntId/thirdPartyId/sessionId 표시 + ID 새로고침 + 경험 초기화 |
| 식별자 | `setThirdPartyId`(= recipient_id) → Customer Attributes(`crs.*`) 매칭 키 |
| Assurance | 화면이 아니라 앱 init(`targetApp`)에서 환경변수로 전역 1회 적용 |
| 미설정 경고 | mbox 빈값/웹 환경이면 `SupportBanner`가 경고(하드코딩 폴백 없음) |

**조회 흐름**

```text
[XT 테스트 버튼]
   → retrieveTargetContent("target-msdk-mbox", "default-content")
   → 반환 콘텐츠 표시 + event-popup JSON이면 모달
   → getTargetIds()로 방문자 식별자 갱신(VisitorPanel)
```

> 구현 상세·SDK 동작 → `docs/main/04_AT_TEST_PAGE_ADOBE_TARGET_INTEGRATION.md §14~15`.

## 9. 가드레일 · 자주 막히는 점

| 증상 | 원인 / 조치 |
|------|-------------|
| 계속 `default-content`만 옴 | 활동 미게시 / mbox 이름 불일치 / 오디언스 불일치(어느 경험도 매칭 안 됨) |
| 의도한 경험이 아닌 게 옴 | **순서(우선순위)** 점검 — 더 위 오디언스에 먼저 매칭됐을 수 있음 |
| All Visitors만 계속 나옴 | All Visitors 경험이 **맨 위**에 있어 아래가 평가 안 됨 → 맨 아래로 |
| 오디언스(`crs.*`)가 안 맞음 | Customer Attributes 구독·Activate / CSV 키 / `setThirdPartyId` 일치 점검(`03 §2.4`) |
| 여러 활동이 겹쳐 엉뚱한 게 보임 | 같은 위치+오디언스 → **우선순위(0~999)** 조정(§7) |
| 웹에서 SDK 동작 안 함 | 네이티브 빌드에서 테스트(웹은 프록시 경로) — `SupportBanner` 경고 확인 |
